## What the last session did

Benchmark only; the rule for the session was: no contender code changes,
no wrapper code, every contender through its plainest entry point.

1. **ab-blake3** (crates.io 0.2.0) is a contender, key `ab-blake3`,
   colour `#c026d3`, in `--all` and default runs. For one message it
   calls `const_hash`, a const fn copy of the reference tree: portable
   at every size, so it runs below the crates.io crate above one chunk
   (0.74 ns/B against 0.40 at 8 MiB on the VM).
2. **The many-messages use case.** `POINTS` holds forty points: the
   twenty input sizes and twenty batch sizes (1 to 16384 messages of
   64 B). Every contender hashes a batch one message per call of its
   plain entry point; ab-blake3 calls `single_block_hash_many_exact::<N>`
   with N the batch size (a const generic, one match arm per point). The
   multithreaded contenders take no part (`Algorithm::takes_part`).
   Samples divide by messages: **ns per message** and **million messages
   per second** (`UseCase::rate_scale`). The duo measurement applies
   unchanged. `Results` is `Vec<Vec<Option<Cell>>>`.
3. **Two plots in one SVG**, `Plot` per use case, one unit switch, one
   on/off state per contender; the script indexes everything by plot.
   The text report has a kernel list and a table per use case.
4. **Golden batch anchors**: `MANY_VECTORS`, the SHA-256 of a batch's
   digests concatenated, from the reference implementation through
   `tools/gen-test-vectors.py` (the driver now takes a message length).
   The one-message table regenerated byte for byte.
5. First VM numbers, many messages: ab-blake3 22.5 ns/msg from 16
   messages up (NEON four blocks at a time), 43–45 below sixteen; BLAKE3
   45, BLAKE3 servil 42.5, SHA-256 31.5, ring 40.4, SHA-1DC 175. At 24
   messages ab-blake3 pays for the eight-block remainder (29 ns/msg).

## Commands

From `/workspace` in the VM (every `git`/`cargo` command takes this `HOME`):

`HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo test --release`

`HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo test --release --features no_sme2`

`HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo test --release --features pure`

`HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo test --release --manifest-path /workspace/test_vectors/Cargo.toml`

`HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo test --release --manifest-path /workspace/bench-hashes/Cargo.toml`

Benchmark runs write `benchmark-results/` relative to the **current
directory**; run them from `/workspace/bench-hashes` so results land in
the repository:

`cd /workspace/bench-hashes && HOME=/workspace/vm/home CARGO_TARGET_DIR=/tmp/target CC=clang-19 TMPDIR=/tmp cargo run --release -- --all`

On the Mac, from `bench-hashes`: `cargo run --release -- --all` (add
`--thorough` for narrower bands). Results overwrite that machine's files;
copy a baseline aside before a comparison. Commit before publishing so the
provenance reads `clean`.

Release: `python3 tools/gen-ver.py X.Y.Z` from a clean tree makes two
version commits and a lightweight tag `vX.Y.Z+<commit>`; push with
`git push origin main` and then the tag by name (`--follow-tags` skips
lightweight tags).

Expected suites: fork 56 library + 16 doc tests (`no_sme2` 55 + 16,
`pure` 46 + 16); official vectors 2; benchmark 5.

Use no timeout for long commands; let progress stream. Never sleep in
commands. If a network operation fails, report it and stop; the user
chooses retries. Never print the credential token. Only `/workspace`
survives VM restarts.
